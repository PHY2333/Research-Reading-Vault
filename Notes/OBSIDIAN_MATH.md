# Notes/OBSIDIAN_MATH.md

Framework: Notes Pro-First 1.2

目标渲染器为 Obsidian / MathJax。本文件规定目标格式、Codex 的上下文修复权限，以及完成应用前的检查步骤。

## 1. 目标格式

行内公式使用美元分隔符：

```md
矩阵满足 $H_XH_Z^T=0$。
```

块公式使用两个独立成行的块分隔符：

```md
$$
C_2 \xrightarrow{H_Z^T} C_1 \xrightarrow{H_X} C_0
$$
```

块公式与相邻正文之间保留合适的空行。需要渲染的数学放在数学环境中；代码示例则保留其原始文本。

目标文件保存为原始 UTF-8 Markdown。Browser 或字符串序列化造成的外层包装，在明确其意图后规范化为实际 Markdown。

## 2. 常见输入形式的规范化

以下形式作为诊断示例：

```text
\(...\)
\[...\]
/(...)
/[...]
$$ equation $$
```

当上下文已明确公式边界时，将行内形式规范化为第 1 节的行内格式，将块形式规范化为独立块公式。

文档中用于说明语法的代码样例保持原样。正式需要渲染的公式按目标格式处理。

## 3. 权限判断

Codex 读取当前段落、相邻公式及必要的已读来源，判断修复后的陈述是否唯一且保持原意。按以下三类处理。

### A. Markdown / Obsidian 外层格式

Codex 可以直接修复：

- 行内或块公式的分隔符；
- 块公式的独立成行、换行与空行；
- callout 中所需的引用前缀；
- 明显误加在需渲染公式外层的代码格式；
- 表格、引用、缩进导致的纯渲染问题；
- 中文标点与公式边界的排版。

修复保持正文措辞、数学陈述和内容顺序。

### B. 可唯一确定的 LaTeX 语法或转义

Codex 可以依据上下文直接修复：

- Browser 或字符串序列化造成的重复反斜杠；
- 作用范围已明确、仅有一种合理闭合方式的花括号；
- 明确的环境名称、命令拼写或矩阵换行语法错误；
- 当前正文与已读来源已经唯一确定的转义问题。

处理反斜杠时区分 LaTeX 命令、矩阵换行和传输转义。每处修复均以其所在数学语境为依据。

### C. 数学内容、语义或多义问题

以下事项交由 Pro 或来源核验：

- 变量、运算、指标、上下标、正负号、转置或共轭的内容选择；
- 等号、包含关系、映射方向、量词的改变；
- 定义域、陪域、前提或结论的改变；
- 公式项的增删或重排；
- 数学解释、证明步骤或教学顺序的调整；
- 具有多个合理解释的括号或分隔符；
- 正文与公式冲突，或来源之间冲突。

即使某个内容修订看起来很小，也按其数学作用判断责任。A、B 类沿应用流程直接处理；C 类保存具体问题并进入内容核验。

## 4. 上下文修复步骤

1. 阅读诊断所在的完整段落。
2. 按需要读取相邻公式和 request 指定来源。
3. 判断属于 A、B 或 C 类。
4. 对 A、B 类编辑 staging；对 C 类记录疑点并停止相关应用。
5. 复读修复前后内容，确认数学陈述、正文含义与顺序保持。
6. 重新运行 checker。
7. 在 `APPLY_REPORT.md` 记录修复类别、简洁摘要及复检结果。

Git diff 保存精确变更。应用报告记录足以理解修复原因和核验结果的信息。

## 5. 表格、callout 与代码示例

表格适合短行内公式。较长推导放在表格外，使公式结构清楚。

Callout 中，块公式的每一行保留引用前缀：

```md
> [!note]- 补充推导
>
> $$
> XZ=-ZX
> $$
```

协议和格式说明中的代码示例属于待保留文本。检查时区分代码样例与 reader-visible 数学；发生工具诊断与文档结构不一致时，记录具体位置和上下文，按任务授权处理工具问题。

## 6. Checker 与完成条件

```bash
python Notes/TOOLS/check_obsidian_math.py <file-or-directory>
```

Checker 提供常见数学分隔符与 Markdown 结构的诊断。Codex 结合全文判断问题并完成权限内编辑；自动规则替换器保持停用。

Reader-visible 文件在最终提交前通过 checker，并完成修复前后的含义核对。权限内的格式修复在当前应用轮完成。修复可能改变数学含义，或上下文修复后仍无法通过检查时，保留原文与诊断，进入流程规定的暂停和核验状态。
